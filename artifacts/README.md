# Как проверить отчёт по файлам демо

В этом каталоге лежат 23 файла одного запуска на синтетических платежах. За 42 дня с 6 января по 16 февраля 2025 года включительно после очистки осталось 30 295 операций. Все временные метки приведены к UTC. Этим файлам соответствует [отчёт с графиками](report.html).

## Загрузка моделей и проверка цифр

Выполните из корня репозитория в активированном окружении Python. Для этой проверки достаточно сохранённых файлов. Подключение к PostgreSQL и повторное обучение не требуются.

```bash
python -m pip install -e .
python scripts/verify_artifacts.py artifacts
```

Скрипт загружает обе модели и восстанавливает их входы по сохранённой схеме. Для каждой модели он пересчитывает ROC-AUC, PR-AUC (Average Precision), Recall@TopK и Precision@TopK на валидации и тесте. Для выбранной модели скрипт сверяет оценку риска и действие по каждой тестовой операции, затем пересчитывает затраты. Для почасовых прогнозов он проверяет факты по SQL-витрине и пересчитывает MAE, RMSE и WAPE. При расхождении команда заканчивается с ненулевым кодом.

### Контрольные числа запуска

- У CatBoost на тесте ROC-AUC составляет 0,9078, а Average Precision — 0,4661. Из 6 772 тестовых операций на дату среза метка была известна для 4 883. По этим операциям посчитаны качество ранжирования и денежные потери.
- Политика одобрила 6 148 операций, передала 356 на проверку и отклонила 268. Расчётные потери от мошенничества составили 4 537,62 против 35 438,65 при одобрении всех операций.
- В тесте 216 часов, из них 8 отмечены как аномальные. По таблице прогнозов можно сверить, например, среднюю абсолютную ошибку SARIMAX для числа платежей. Она равна 6,4572 операции в час.

## Где искать исходные цифры

| Что проверить | Файлы и способ проверки |
| --- | --- |
| Входные данные | [Очищенные платежи](clean_transactions.parquet), [аудит очистки](data_audit.json) и [параметры запуска](run_info.json) содержат операции, число удалённых дублей, границы выборок и параметры генератора. |
| Вход моделей | В [транзакционной витрине](transaction_mart.parquet) одна строка соответствует одной операции. [Схема признаков](models/feature_schema.json) задаёт порядок 32 признаков и категории, с которыми обучались модели. |
| Модели риска | [CatBoost](models/catboost.cbm) и [LightGBM](models/lightgbm.txt) содержат обученные деревья. Результаты их сравнения приведены в [метриках](risk_metrics.csv), вклад признаков — в [таблице важности](feature_importance.csv). |
| Почему операция попала на проверку | Найдите её по `transaction_id` в [тестовых решениях](test_scored.csv) и сравните `score` с порогами в [параметрах модели](risk_summary.json). Поле `label_mature` показывает, была ли метка известна на момент оценки. |
| Пороги, лимиты и стоимость ошибок | [Кандидаты на валидации](validation_policy_candidates.csv) показывают результат оптимизации для каждой модели. [Сравнение политик](policy_metrics.csv) содержит объём проверки, потери и ожидаемые ошибочные отклонения. |
| Прогноз нагрузки | [Часовая витрина](hourly_mart.parquet) содержит факты по категориям мерчантов. Прогнозы обоих методов и факты за каждый час находятся в [валидации](forecast_validation.csv) и [тесте](forecast_test.csv). Рядом лежат [метрики](forecast_metrics.csv), [настройки и выбранные методы](forecast_summary.json) и [прогноз на следующие 24 часа](forecast_next_24h.csv). |
| Аномалии и ручная проверка | Для каждого [аномального часа](anomaly_hours.csv) указаны факт, прогноз, отклонение, порог и возможная причина. В [почасовой нагрузке](review_load.csv) можно сравнить ожидаемое и фактическое число ручных проверок. |

## Происхождение и повторный запуск

Файлы созданы в [запуске GitHub Actions № 45999624798](https://github.com/Maxo0on/payment-risk-postgresql/actions/runs/45999624798) на PostgreSQL 16. Использованные версии Python и библиотек записаны в [environment.txt](environment.txt).

Для обучения с нуля сначала поднимите PostgreSQL и настройте подключение по [инструкции проекта](../README.md#быстрый-запуск). Для повторного прогона используйте те же период и seed.

```bash
python -m payment_risk --days 42 --seed 42 --out results_reproduced
python scripts/verify_artifacts.py results_reproduced
```
